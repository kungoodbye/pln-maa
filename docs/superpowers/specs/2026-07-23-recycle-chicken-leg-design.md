# 小鸡腿资源回收循环设计

## 目标

在游戏主界面启动一个独立的 MaaFramework 任务，自动回收背包中的小鸡腿：

1. 点击资源回收箱，并以“资源回收桶”标题确认页面已打开。
2. 从背包顶部页开始搜索小鸡腿；当前页没有时向下搜索下一页，最多滑动三次。
3. 找到后点击小鸡腿，在数量弹窗点击 `MAX` 和“确定”，再点击“回收”。
4. 识别回收成功提示后点击安全空白处关闭提示。
5. 回到背包顶部，继续搜索；初始页加三次滑动后仍找不到小鸡腿时正常完成。

该任务不修改现有的 `Alchemy.EnsureUI` 状态链，也不使用 Python 自定义 Agent。

## Pipeline 结构

新增 `assets/resource/pipeline/recycle.json` 和界面任务“回收小鸡腿”，入口为 `Recycle.OpenBin`。

- `Recycle.OpenBin`：使用固定坐标点击主界面的资源回收箱。
- `Recycle.EnsurePage`：OCR 识别“资源回收桶”；未识别即异常结束，避免在错误页面发送背包操作。
- `Recycle.FindPage1` 至 `Recycle.FindPage4`：在背包网格安全区域以 `TemplateMatch` 查找 `recycle/chicken_leg.png`，按视觉顺序点击第一个命中。页面 1 至 3 未命中时各执行一次向下滑动；页面 4 未命中时进入正常结束节点。
- 每个页面各有一条数量确认链：等待“输入数量”、点击 `MAX`、OCR 点击“确定”、确认回收槽已放入小鸡腿、OCR 点击“回收”、等待“获得”提示、点击安全空白处关闭提示。
- 成功链根据命中页面执行零至三次反向滑动回到顶部，再回到 `Recycle.FindPage1`。这样每轮重新从顶部搜索，避免回收后背包重排而遗漏目标。

所有坐标继续采用项目现有的 1280×720 标准坐标；背包滑动复用炼金任务在网格内的安全滑动带。`MAX`、回收按钮和成功提示的点击均以前序界面识别为前提。

## 资源与失败处理

- 新增一张仅包含小鸡腿主体、裁掉格子边框和数量文字的识别模板 `assets/resource/image/recycle/chicken_leg.png`，从用户提供的回收页面截图制作，并使用与炼金物品模板一致的绿色透明掩码规则。
- 资源回收箱使用固定位置点击，不额外引入脆弱的主界面模板。
- 页面标题、数量弹窗、回收按钮和成功提示任一未出现都视为异常；不把异常误报为“没有小鸡腿”。
- 仅“第 4 个搜索页没有小鸡腿”是正常结束条件，焦点日志明确说明已完成三次下滑搜索。

## 验收

- 从主界面能打开资源回收桶，并在标题确认后才搜索背包。
- 顶部页、第一次、第二次或第三次下滑后的页面存在小鸡腿时，都能选择整组并完成回收。
- 回收成功提示关闭后继续扫描；已在第 2 至第 4 页完成回收时，背包会回到顶部后再开始下一轮。
- 初始页和三次下滑后的页面均无小鸡腿时，任务以正常完成状态停止。
- 现有“连续炼金”任务入口、JSON 内容和行为保持不变。
