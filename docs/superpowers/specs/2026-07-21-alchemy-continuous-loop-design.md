# 炼金连续循环 JSON 设计

## 目标与范围

在游戏已经打开合成页面、背包按“物等小→大”排序的前提下，使用 MaaFramework JSON Pipeline 自动执行连续炼金。

- 主料固定为小齿轮。
- 副料允许草菇或小石头。
- 只搜索背包第一屏，并严格限制在背包网格 ROI 内。
- 候选按从上到下、每行从左到右的顺序选择第一个，不比较堆栈数量。
- 不滚动背包，不引入 Python Agent，不支持其他配方。

本设计取代旧设计中的“比较最大堆栈”和“放料后不开始合成”，但保留合成页面检查、排序检查、数量弹窗确认和异常截图。

## 状态机

1. `EnsureUI`：在左上角固定 ROI 识别“合成”。失败即异常终止。
2. `EnsureSort`：在背包上方识别“物等小→大”。失败即异常终止。
3. `EnsureMain`：检查上方主料槽。
   - 主料槽已有小齿轮时进入 `EnsureSub`。
   - 主料槽为空时进入 `RefillMain`。
4. `RefillMain`：在背包第一屏寻找第一个小齿轮，点击后等待“输入数量”，再点击“确定”。第一屏没有小齿轮时正常结束任务。
5. `EnsureSub`：检查右侧副料槽。
   - 副料槽已有草菇或小石头时进入 `StartAlchemy`。
   - 副料槽为空时进入 `RefillSub`。
6. `RefillSub`：在同一个背包 ROI 内寻找草菇或小石头中的第一个可见候选，点击并确认数量。两种副料都不存在时正常结束任务。
7. `StartAlchemy`：识别并点击右下角“合成开始”。
8. `WaitRunning`：识别“停止”，证明连续合成已经启动。任务不主动点击“停止”。
9. `WaitFinished`：持续等待“停止”消失且“合成开始”重新出现，表示当前材料组合已经停止连续合成。
10. `DismissResult`：点击结果弹层中的安全空白位置，关闭最终结果弹窗。
11. 返回 `EnsureMain`，根据空槽补主料或副料，然后再次开始连续合成。

## 识别和点击规则

- 所有坐标使用 MaaFramework 的 1280×720 标准坐标。
- 背包物品识别不得覆盖炼金槽、合成按钮或其他界面区域。
- 物品模板裁剪时排除右下角动态数量、左上角绿色物等数字和格子边框。
- 小齿轮、草菇和小石头使用模板匹配；匹配结果按网格视觉顺序取第一个。
- 主料槽和副料槽分别使用独立 ROI 判断“已有材料”或问号空槽。
- 数量弹窗保持默认数量 1，只识别并点击“确定”。
- 关闭结果弹窗的点击点不得落在“停止”“合成开始”、背包物品或炼金槽上。

## 结束和异常

材料耗尽是正常结束：

- 需要补主料时，第一屏找不到任何小齿轮。
- 需要补副料时，第一屏同时找不到草菇和小石头。

任一必需类别无法补充便停止，因为缺少主料或副料都不能继续合成。正常耗尽不保存失败截图。

以下情况属于异常，应立即失败并由 `save_on_error` 保存截图：

- 无法确认合成页面或排序状态。
- 点击材料后未出现数量弹窗。
- 未找到或无法点击“确定”。
- 点击“合成开始”后未识别到“停止”。
- 连续合成或结果弹窗状态在超时时间内无法判定。
- 关闭结果后无法识别主料槽或副料槽状态。

## 验收标准

- 初始空槽能够自动补入一个小齿轮和第一个可见的合法副料。
- 能够点击“合成开始”，并通过“停止”确认正在连续合成。
- 连续合成结束后能够关闭结果弹窗，判断耗尽的是主料还是副料。
- 仅补充空缺类别；另一槽仍有材料时不得重复放料。
- 补料成功后重新开始连续合成。
- 第一屏缺少必需类别时正常结束；非材料耗尽错误则失败并保留截图。
