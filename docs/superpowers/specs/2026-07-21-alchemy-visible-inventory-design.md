# 炼金第一屏选材自动化设计

## 目标

在《飘流幻境新世界》的合成页面中，自动从当前第一屏背包里选择数量最多的小齿轮和小石头，分别确认数量为 1，最后验证两个材料已进入指定炼金槽位。任务不点击“合成开始”，因此不会实际消耗材料。

## 范围

第一版包含：

- 通过左上角“合成”二字确认当前已经处于合成页面。
- 确认背包排序状态为“物等小→大”；第一版将其作为运行前提，不正确时立即失败。
- 只扫描当前可见的第一屏背包格子，不滚动背包。
- 在所有可见的小齿轮堆栈中选择数量最多者；数量相同时选择视觉顺序中的第一个。
- 用相同规则选择小石头。
- 每次选择材料后确认“输入数量”弹窗已经出现，并点击“确定”。默认数量保持为 1。
- 验证上方槽位是小齿轮、右侧槽位是小石头。
- 任一步骤失败时终止任务，并由 MaaFramework 的 `save_on_error` 保存失败截图。

第一版不包含：

- 从其他游戏页面导航到合成页面。
- 滚动背包或跨页比较堆栈数量。
- 点击“合成开始”。
- 通用配方配置、连续炼金或材料不足后的补充策略。

## 技术方案

采用“JSON Pipeline 编排 + Python 自定义识别器”。

JSON Pipeline 负责页面状态、排序状态、交互步骤、弹窗等待、确认按钮和最终槽位验证。Python Agent 只负责一个边界清晰的任务：在指定背包 ROI 内识别同类物品候选、读取堆叠数量，并返回应点击的格子。

不采用纯 JSON 逐格比较，因为 Pipeline 不适合动态比较多个 OCR 数字；也不让 Python 接管完整流程，以保留 MaaFramework Pipeline 的可视化调试、失败节点和截图能力。

## 项目结构

- `assets/interface.json`：项目元信息、Win32 控制器、Python Agent 和任务入口。
- `assets/resource/pipeline/alchemy.json`：完整的最小炼金任务流水线。
- `assets/resource/image/alchemy/`：小齿轮、小石头、弹窗和槽位状态模板。
- `agent/item_selector.py`：MaaFramework 自定义识别器适配层。
- `agent/inventory_grid.py`：720p 背包 ROI、格子几何和安全点击区域。
- `agent/stack_quantity.py`：候选格右下角数量 OCR 与可靠性校验。
- `agent/selection.py`：不依赖 MaaFramework 的确定性选择规则。
- `tests/`：纯函数测试和截图夹具测试。

现有 `.create-maa-project` 仅作为本地调试运行缓存保留，不进入版本控制。

## 流程

1. OCR 左上角固定 ROI，必须识别到“合成”。未命中时任务失败。
2. OCR 右上角排序文本。
3. 必须识别到“物等小→大”，否则立即失败；命中后进入选材。
4. 调用物品选择器查找小齿轮。
5. 点击选择器返回的安全点击区域。
6. 必须识别到“输入数量”弹窗，随后点击“确定”。
7. 调用同一选择器查找小石头，并重复弹窗确认步骤。
8. 在上方槽位 ROI 匹配小齿轮，在右侧槽位 ROI 匹配小石头。
9. 两个槽位均验证成功后结束任务。

## 第一屏物品选择算法

背包只使用 720p 标准坐标中的固定网格 ROI。视觉顺序定义为从上到下逐行扫描，每行从左到右。

选择器执行以下步骤：

1. 在背包 ROI 内模板匹配目标物品的所有候选。
2. 按候选中心所在格子去重，同一格只保留置信度最高的匹配。
3. 丢弃落在背包 ROI 外、不能映射到有效格子或置信度不足的结果。
4. 对每个候选只 OCR 格子右下角的堆叠数量区域，避免读取左上角绿色物等数字。
5. 每个候选必须得到唯一、明确、置信度合格的正整数。缺失、多个数字、非数字或低置信度均使本次选择失败。
6. 使用 `(-quantity, row, column)` 排序，第一项即为目标。
7. 返回目标格中心附近的小型安全点击区域，不返回整张图标框，避免随机点击落在边缘。

例如多个小齿轮数量均为 200 时，选择视觉顺序中的第一个 200；小石头数量为 106 和 200 时，选择 200。

## 识别素材

所有模板和 ROI 均以 MaaFramework 的无损 720p 截图为基准。库存物品模板从背包格内部裁剪，避开动态数量文字、绿色物等数字和格子边框。最终槽位验证使用独立 ROI，避免把背包中的同类图标误判为已放入槽位。

现有错误截图可作为首批夹具，但正式阈值以新的 MaaFramework 实时截图调试结果为准。

## 失败处理与可观测性

以下情况必须立即失败，不做降级点击：

- 未识别到“合成”。
- 无法确认当前为“物等小→大”。
- 第一屏不存在目标物品。
- 任一候选的数量无法可靠读取，因此无法证明最大值选择正确。
- 点击物品后没有出现“输入数量”。
- “确定”按钮未出现或点击后弹窗未关闭。
- 最终任一槽位未匹配到预期材料。

自定义识别器在日志中输出目标类型、每个候选的行列、模板置信度、OCR 数量与置信度、最终选择以及失败原因。MaaFramework 开启 `logging` 和 `save_on_error`，以便将失败节点与截图对应起来。

## 测试策略

### 纯函数测试

- 单一候选可直接选中。
- 不同数量选择最大值。
- 最大数量并列时按行优先选择第一个。
- 行优先顺序优先于模板匹配分数。
- 无候选时报错。
- 数量缺失、含多个数字、非正整数或低置信度时报错。

### 截图夹具测试

- 背包 ROI 不包含炼金槽位和其他界面区域。
- 现有 720p 截图能够定位多个齿轮候选。
- 能够读取候选格右下角数量，并复现最大值与并列规则。
- 能够定位石头候选并选择数量较大的格子。
- 安全点击区域完全位于目标格内部。

### 配置与联调验证

- 使用模板自带的 Schema 校验 `interface.json` 和 Pipeline。
- 启动 MFAAvalonia，连接 `UnityWndClass` 游戏窗口。
- 执行任务并确认只放入小齿轮和小石头，没有点击“合成开始”。
- 检查任务日志、最终截图和背包数量变化与预期一致。

## 验收标准

在游戏已打开合成页面、第一屏可见至少一个小齿轮和一个小石头、排序可设为“物等小→大”的前提下：

- 自动选择第一屏数量最多的小齿轮和小石头。
- 最大数量并列时选择视觉顺序中的第一个。
- 两次数量弹窗均保持数量 1 并完成确认。
- 最终画面满足上方槽位为小齿轮、右侧槽位为小石头。
- 不触发实际合成。
- 任一前提或识别结果不可靠时，任务失败且保存错误截图。
